# Patrones de los exámenes y prácticas de Aplicaciones Web

## Para qué sirve este documento

Este archivo resume patrones observados en los diez PDFs aportados. Los exámenes son referencias históricas: **no permiten conocer con certeza el próximo enunciado**. Ante una actividad nueva, el PDF y los archivos de esa actividad mandan sobre este resumen. Los PDFs de Hertz titulados `Caso Hertz` y `Caso Hertz (1)` son esencialmente duplicados del mismo enunciado PC2 202520, no dos patrones independientes.

## 2. Patrones frontend reconocidos

### A. Music Explorer PC1 2026-1
- API: `https://itunes.apple.com/search?term=daft%20punk&entity=song&limit=12`.
- Mostrar `trackName`, `artistName`, `collectionName`, `primaryGenreName`, `releaseDate`, `trackViewUrl` y `artworkUrl100`; la imagen usa `artworkUrl100` y el enlace abre `trackViewUrl` en una pestaña nueva.
- Toolbar `Fake Music Catalog API`, sección `All Songs`, footer con el texto de copyright de 2026 y `Developed by` con código, nombre y apellido.
- Vue 3/Vite, PrimeVue basado en Material Design y Axios. Textos de interfaz en inglés, ARIA en vistas/componentes principales, WebStorm, responsive web design.
- Dominios: `public` (home, toolbar, footer) y `music` (componentes, servicios y entidad).
- Archivos sugeridos: `song-card.component.vue`, `song-list.component.vue`, `song-api.service.js`, `song.entity.js`; kebab-case y `pv-` para componentes PrimeVue como `<pv-card>`.
- Los archivos fuente creados deben tener comentarios JSDoc con `@summary` y `@author`.
- Fuera de alcance: Sidebar, internacionalización, routing, autenticación, barra de búsqueda, paginación y favoritos. No añadirlos.

### C. SuperHero PC1 2024-2

### E. Tend Parcial 2025-1 (frontend + JSON Server)
- JSON Server 0.17.4, ejecutado desde `server` con `json-server --watch db.json`.
- Endpoints: `GET /plots`, `GET /plots/:id`, `POST /inspections` en `http://localhost:3000`.
- Rutas: `/` redirige a `/home`; `/home`; `/plots/:id/inspections`; lazy loading; ruta no encontrada muestra la ruta fallida y botón a Home.
- Toolbar con logo vía Clearbit Logo API, texto `Sustainable Urban Farming`, Home e idioma EN/ES. Inglés por defecto; i18n global y preset PrimeVue Aura.
- Home: tabla Registered Plots con id, name, location, hectares, monitoringStartDate; botón Register Inspection deshabilitado si `monitoringStartDate` es posterior a hoy.
- Inspección: plotId de solo lectura desde la ruta; observations, recommendedActions y cropStatus (Good/Warning/Critical) obligatorios; validar que el plot exista antes de POST. Critical muestra Toast warning con mensaje exacto `Critical condition detected. Immediate action required.`; éxito muestra Toast success `Inspection successfully registered.`; después limpiar el formulario excepto plotId.
- Arquitectura pedida: `public`, `shared`, `plot-management`; Vue 3/Vite, PrimeVue, PrimeFlex, PrimeIcons, Axios, Vue Router, Vue-i18n, JavaScript orientado a objetos, ARIA, archivos `.component.vue` y `.service.js`, pages solo para rutas, componentes reutilizables en components, README y ZIP sin `node_modules`.

## 3. Patrones backend reconocidos

### A. SuperHero PC2 2024-2 (C#/.NET 8)
- Endpoint de operación: POST `/api/v1/heros`; responde 201 con resource e ID generado y usa status/body correcto ante errores.
- Bounded context `HERO` y `Shared`; persistencia MySQL, esquema `local-hero`.
- `Continent` enum: 1 AMERICAN, 2 EUROPE, 3 AFRICA, 4 ASIA, 5 OCEANIA. El request indica continent como string que coincide con el nombre; valida contra enum. `heroId` va en la ruta, no en body, y es un ID positivo de otro contexto fuera de alcance.
- `registerEmailAddress` es value object `EmailAddress`, válido/no vacío/máximo 50; `heroPlace` obligatorio máximo 50; country máximo 250; ability máximo 50; registro fecha/hora generada por sistema (no enviada por cliente). ID primario autogenerado. Evitar duplicados según combinación heroId + continent + country + place. Aggregate root con CreatedAt/UpdatedAt.
- DDD bounded contexts/layers, CQRS, value objects, enum, ORM convention snake_case y tablas plurales en Shared, propiedades en Entity, URLs minúsculas, XML docs en inglés con `<remarks>` de autor, OpenAPI, exceptions. Sin CORS, security ni testing porque están explícitamente fuera del alcance.

### B. Hertz PC2 2025-2 (C#/.NET 9)
- Endpoint único: POST `/api/v1/rental-orders`; ID autogenerado. HTTP 201 con resource y el ID generado; mensajes de error con status adecuado.
- Bounded context `services` con `RentalOrder` y `EVehicles`; `Shared` para elementos comunes. MySQL, esquema `Hertz` (preserva el casing indicado para el esquema aunque los identificadores SQL puedan tener sus convenciones propias).
- Campos: rentalOrderId, customer, vehiclesId, plate, requestedAt, address (owned attribute: Street, City, PostalCode), amount, createdAt, updatedAt. Reglas: no repetir customer + vehiclesId; amount mayor que cero; requestedAt no menor a la fecha del sistema; una plate no puede pertenecer a vehiclesId diferentes; enum EVehicles con 1 Picanto, 2 Soluto, 3 Corolla, 4 RAV4, 5 Versa, 6 Sportage. customer obligatorio max 90; plate max 12; cada parte de address obligatoria max 40; ID autogenerado.
- Response incluye rentalOrderId, customer, vehiclesId, plate, requestedAt y address. Excluye amount y auditoría. El texto introductorio menciona amount double pero en la especificación de persistencia dice int: señalar la discrepancia; dar prioridad a la especificación concreta de persistencia si no hay aclaración adicional y explicar la decisión.
- DDD, CQRS, layers Domain/Application/Interfaces/Infrastructure, Resource, Assembler, MySQL/EF Core, rutas en minúsculas, clases/props/métodos PascalCase, campos privados camelCase, SQL snake_case/tablas plurales, XML docs en inglés con `<remarks>`, OpenAPI, README en inglés, manejo de excepciones. Fuera de alcance: CORS, Security, Testing.

### C. ClickUp Final 2025-2 (C#/.NET 9)
- Endpoints y operaciones acotadas: POST `/api/v1/folders` (id autogenerado, 201, response sin auditoría) y GET `/api/v1/spaces` (colección, sin auditoría).
- Bounded contexts `Folder`, `Space` y `Shared`; Folder/EVisibilityType pertenecen a Folder; Space/EState a Space. MySQL, esquema `clickup`; raíz de solución `ClickUp.Platform.u<studentcode>` y proyecto API `eb<NRC>u<studentcode>.API`.
- Space inicial: id 1..4 con workSpaceId 4,3,2,6 y name school/family/friends/sport; states ACTIVE/INACTIVE; color tags en hexadecimal. `EState`: 0 ACTIVE, 1 INACTIVE. `EVisibilityType`: 0 PUBLIC, 1 INTERNAL, 2 PRIVATE. Space seeding al iniciar si faltan registros.
- Folder requiere id autogenerado, spaceId válido, name, description, visibilityType, createdBy válido como value object y generatedAt. `generatedAt` no puede ser futuro; request admite `yyyy-MM-dd HH:mm:ss`; visibilityType y State se reciben como string.
- Registrar Folder comprueba el space/workSpace correspondiente; al guardar emite `FolderRegisteredEvent` con spaceId y name. Un handler actualiza el name del Space referenciado si difiere. Implementar ACL entre bounded contexts; integration event declarado en Shared para el monolito y handler en el contexto receptor, conforme al enunciado.
- Aggregate Roots Folder/Space tienen CreatedAt/UpdatedAt generados automáticamente. Enunciado especifica `EntityFrameworkCore.CreatedUpdatedDate`, Fluent API, naming strategy (snake_case, tablas plurales), `Cortex.Mediator` para event handling y Accept-Language EN/EN-US o ES/ES-PE, defecto inglés. OpenAPI, XML docs en inglés, `<remarks>` con autor, README en inglés, manejo de excepciones. Fuera de alcance: CORS, Security y Testing.

## 4. Lecciones comunes que debe aplicar el agente

1. **No existe una única plantilla universal.** La PC1 Music es simple y excluye routing/i18n; Tend sí exige ambas. Hussmann requiere Pinia por bounded context, pero un examen que no lo pide no debe recibirlo por defecto.
2. **La sección fuera de alcance tiene valor contractual.** No agregar funciones exclusivas de otros exámenes.
3. **La rúbrica importa.** En varios frontend, los criterios de mayor peso son features y UI; en backend, son endpoints, persistencia y reglas de negocio. Prioriza por los pesos de la rúbrica adjunta a la actividad actual, no por el peso de este resumen.
4. **Payload y response no son la misma cosa.** IDs y auditoría suelen ser generados por servidor; ciertos campos se persisten, pero se excluyen de la respuesta. Construye Resource/Assembler cuando se solicite.
5. **Validación de negocio no equivale a validación de forma.** Comprueba reglas de combinación y referencias en la capa de dominio/aplicación apropiada, no solo con atributos del request.
6. **Datos relacionados requieren resolver las relaciones reales.** Hussmann pide nombres/modelos, no mostrar IDs en su lugar.
7. **No inventar metadatos.** Sustituye NRC, código, sección, autor y año solo a partir del enunciado actual. Muestra como placeholder cualquier valor que falte.
8. **Las muestras antiguas pueden contener erratas o contradicciones.** Indica las contradicciones materiales y justifica la interpretación elegida; no transformes detalles históricos en reglas del curso vigente.

- `PC1`/`Parcial` y `PC2`/`Final` solo seleccionan un patrón predeterminado, no garantizan el tipo de tecnología del futuro enunciado. El contenido del PDF actual manda.

- No subir valores reales de `.env*` ni `appsettings*.json` a fuentes de conocimiento.
